## 0.4 防踩坑（必读）

- `app.js` 是覆盖层结构，同名函数**最后一次赋值生效**。修改前先确认改的是最终生效的那份。
- **判断某个函数是否生效，不能只看它“被谁调用”**，必须沿覆盖链查到文件末尾。实例：V10.1.1 历史兼容层里有一个旧版时序特征页调用了旧热力图 `forecastCorrelationMatrixV101`，但该特征页已被文件后部“V10.2 final activation”重新指向带阈值面板的版本（最终调用 `forecastCorrelationMatrixV102`）。已用浏览器实测确认：页面上 `data-forecast-correlation-threshold-v102` 输入框和两个按钮真实存在。
- **v5/v6 的 DOM 注入器对所有页面无差别执行**，会识别 `[data-correlation-unsaved]` 等钩子。任务 A 新增的"尚未应用"提示**必须使用带 v1032 后缀的独立数据属性**，不能复用分类版的 `data-correlation-unsaved`，否则分类版的 bind 可能误抓时序页元素。
- `.correlation-actions` 的样式已存在且完整（flex、对齐、输入框 90px 宽），任务 A 直接复用，**不要为它写新 CSS**。
- 字符串注入/替换都要做幂等检查。

## 1. 任务 A：时序热力图按钮区对齐分类/回归版

### 1.1 目标效果

时序"特征相关性热力图"的按钮区与分类/回归版结构一致：

- 预警阈值输入框、「尚未应用」提示、「确定修改」按钮统一包在 `.correlation-actions` 容器里。
- **删除**「恢复 0.80」按钮及其事件绑定。
- 不给时序加"自动处理高相关特征"按钮（时序产品定义是"高相关只提示、不自动删除"，这是有意的差异）。

### 1.2 修改模板

- **定位**：搜索 `function forecastCorrelationMatrixV102`（V102 结尾，全文件只有一个）。该函数有两个 return：第一个是“数值特征不足 2 个”的早退分支（**不要动**）；第二个 return 才是带阈值输入框和按钮的完整面板，改它。
- **现状结构**：`panel-head > div(标题) + label(输入框) + [恢复 0.80] + [确定修改]`，label 和按钮散在 panel-head 里。
- **改为**：`panel-head > div(标题) + <div class="correlation-actions">label(输入框) + span(尚未应用提示) + [确定修改]</div>`。
- 「尚未应用」提示：`<span>` 元素，带 `data-forecast-correlation-unsaved-v1032` 属性和 `hidden` 初始状态，放在输入框 label 之后、「确定修改」之前。
- 「确定修改」按钮保留 `primary` 样式与原有动作 `forecast-apply-correlation-v1024`。
- 模板中删除 `${button('恢复 0.80', 'forecast-reset-correlation-v1024')}` 这一段。

### 1.3 删除"恢复 0.80"的事件绑定

- **定位**：V10.2.4 的 `bind` 包装器内搜索 `forecast-reset-correlation-v1024`。
- **删除**：该 `if` 分支整个移除；保留 `forecast-apply-correlation-v1024` 分支不动。

### 1.4 接上"尚未应用"提示的显隐

- 在 V10.2.4 `bind` 中相关性输入框已有的 `input` 监听里追加一行：把页面上的 `[data-forecast-correlation-unsaved-v1032]` 提示设为可见。
- 「确定修改」点击成功后：现有逻辑会 `save(); render();`，模板重新渲染时 span 默认 `hidden`，提示自动消失——**不需要额外代码**。
- 原理说明（写给执行者）：提示的显示是纯 DOM 操作（改 `hidden` 属性），不进状态、不持久化。

### 1.5 任务 A 完成检查

- [ ] 修改输入框数值后出现橙色「尚未应用」；点「确定修改」后提示消失、阈值生效。
- [ ] 页面任何位置不再出现「恢复 0.80」。

## 3. 任务 C：智能选型创建实验的命名对齐普通规则

### 3.1 背景

- 现状：智能选型创建实验的名称是 `{模型名} 智能选型`（冲突时追加序号），导致实验标题、实验名称输入框、实验列表卡片都带"智能选型"标注。
- 目标：与普通实验命名完全一致——`{模型名} {两位序号}`，例如"基线预测 01"、"决策树分类 02"。

### 3.2 修改命名逻辑

- **定位**：搜索 `${modelNameDisplay} 智能选型`，在 `create-from-smart-selection-v103:` 分支内。
- **改为**（与普通创建流程同一口径）：
  1. 模型名改用 `modelName(modelId)`（平台统一模型名函数，分类得到"决策树分类"、时序得到"基线预测"），**不要**再用智能选型目录的 `name`。
  2. 序号 = 当前数据集内**同类型**实验数量 + 1，用 `String(序号).padStart(2, '0')` 补两位。
  3. 实验名 = `{模型名} {序号}`。
  4. 删除原有的全局重名 while 循环（普通规则不需要）。
- **参考**：分类普通创建在 `add-model:` 分支、时序在 `add-forecast-model-v10:` 分支，两者的命名表达式就是模板。
- **保留不动**：`smartSelectionId: record.id` 字段（内部追踪用，界面不显示）、`experimentMap` 写入、固定参数注入、创建后跳转。

### 3.3 旧数据一次性迁移

在文件末尾最终激活三行**之前**追加一段一次性迁移（幂等）：

1. 遍历 `state.experiments` 所有实验。
2. 名称中包含 `智能选型` 的实验进入待迁移列表（判断用 `includes`，不区分后缀形态）。
3. 对每个待迁移实验按 3.2 的规则重新命名：
   - 模型名 = `modelName(实验.type)`；
   - 序号 = 该实验所属数据集内、同类型、且名称**不含**"智能选型"的实验数量 + 1；
   - 若算出的新名与任何现有实验重名，序号继续 +1 直到不重名。
4. 同一数据集同一类型有多个待迁移实验时，按数组遍历顺序依次递增序号。
5. 迁移后 `save()`。
6. **幂等性**：迁移过的名字不再含"智能选型"，下次启动自然跳过，不需要额外标记位。

### 3.4 任务 C 完成检查

- [ ] 从智能选型结果页创建实验，新实验名为"基线预测 01"式普通命名，不再出现"智能选型"。
- [ ] 同一模型第二次从另一轮选型创建时序号递增（普通"复制实验"流程不受影响）。
- [ ] 迁移执行后，旧的"基线预测 智能选型"实验名变成普通命名；刷新页面迁移不会重复执行、不会再次改名。
- [ ] 名称迁移不与任何现有实验重名。
- [ ] 实验的 `smartSelectionId` 字段仍在（结果页"查看实验"按钮的回跳依赖它）。
- [ ] 结果页"创建实验后按钮变查看实验"的行为不受影响。

## 6. 常见错误速查

| 症状 | 最可能原因 | 修复方向 |
| --- | --- | --- |
| 「恢复 0.80」还在页面上 | 只删了 bind 没删模板按钮（或反之） | 1.2 与 1.3 必须同时做 |
| 「尚未应用」在分类页也出现/不显示 | 复用了分类版的 `data-correlation-unsaved` 属性名 | 必须用 `data-forecast-correlation-unsaved-v1032` |

| 迁移反复执行/名字越改越长 | 迁移判断条件写错 | 只对"名称包含智能选型"的实验改名，改后不再命中 |
| 迁移后两个实验重名 | 没做重名递增 | 3.3 第 3 步的序号递增直到唯一 |
