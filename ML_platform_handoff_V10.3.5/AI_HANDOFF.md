# ML Studio AI 交接摘要

> 后续大模型先读本文件。它记录用户截至 V10.2.2 的最终决定；冲突时以用户最新明确指令为准，再参考 `PROJECT_HANDOFF.md` 和 `机器学习训练平台前端开发文档.md`。不要从旧需求或旧代码恢复已取消功能。

## 1. 项目目标与边界

- 面向机器学习初学者的零代码前端演示平台，以固定向导完成数据检查、特征准备、模型训练、训练结果、报告、模型库和模拟 API 流程。
- 当前支持二分类、多分类（3–20 类）、普通回归、单实体单序列时序预测；时序允许一个目标列和多个外部特征。
- 当前没有真实后端。训练、统计、报告、预测区间和 API 响应均为稳定 Mock，用于完整展示前端流程；不要因“数据是 Mock”删除演示内容，也不要宣称可用于真实业务。
- 技术栈仅为原生 HTML、CSS、JavaScript 和 LocalStorage，无构建步骤，可直接打开 `index.html`。
- 当前功能基线：V10.3.5；在 V10.3.4 基础上继续做智能选型 UI/交互优化，分支 `main`。

- 固定流程：`数据检查 → 特征准备 → 模型训练 → 训练结果`；报告是结果详情，不是第五步。
- 特征准备：训练/验证划分、阈值校验、自动筛选、手动纳入/排除、相关性热力图和防数据泄漏提示。

## 3. 关键设计决策

- 用户已停用 React。现行产品只维护本交接目录（`ML_platform_handoff_V10.2.2`）下的原生 JS/CSS 页面。
- “零代码”采用固定向导，不采用自由画布、节点、连线、拖拽或缩放。
- 创建项目只选分类、回归或时序；目标列在数据集内选择。分类项目由首个有效数据集锁定二分类/多分类，同一项目不混合子类型。
- 智能选型不等于最终模型性能承诺：它只是固定参数基准比较，推荐模型仅用于帮助确定后续重点调参方向；创建实验后仍需正常训练才能产生报告、保存到模型库和 API。
- 同一分类子类型内可更换合规目标列；已有实验、模型快照或 API 时必须复制数据集后修改。另一子类型应新建项目。
- 二分类保留自动预选且可修改的正类；多分类没有正类。多分类不做互信息，使用归一化方差；10 类及以上不展示混淆矩阵。
- 所有流程统一称训练集/验证集，不称测试集，不加入交叉验证。填充、编码、标准化和筛选统计只基于训练集，避免泄漏。
- 自动筛选与恢复推荐阈值是不同动作：恢复只改数字；点击自动筛选才批量更新特征，之后仍允许手动调整。
- 时序只支持单实体、单序列、单目标，但允许多个历史外部特征。上传数据只含历史记录，不包含未来目标或未来特征。
- 时序未来外部特征只在模拟 API 请求中逐期提供；基线和指数平滑只依赖目标历史，ARIMA 有外部特征时为 ARIMAX，Prophet/LightGBM 可使用外部特征。
- 时序滚动回测固定 3 轮，不让初学者选择是否启用；预测期数受频率和历史长度限制。
- 日历特征开关位于特征管理，生成星期、月份、季度、周末等字段。时序自动筛选只用历史缺失率和归一化方差；相关性、最佳滞后及热力图仅作参考。
- 保存训练结果的含义是把所选参数结果及不可变快照写入模型库；保存后必须跳到对应模型库实验详情，并可返回训练结果。
- 模型库保留跨数据集比较风险提示，不输出跨配置“全局最佳”。页面设计保持简洁，不增加重复说明、额外状态或未经确认的模块。

## 4. 用户纠正过的错误（禁止回退）

- 不要讨论或实现真实求解器、训练服务等后端细节；当前任务是前端演示。
- 多分类报告只能参考二分类的排版，不能照搬二分类专属指标；多分类训练集/验证集指标总览必须置顶，数据概览不能放在不合理的开头位置。
- 曾出现模型报告打不开和 `Cannot set properties of null (setting 'title')`；修改路由/报告时必须回归该入口。
- 多分类阈值体验必须与二分类对齐：百分号位置、PSI 默认值、越界标红、行内提示和相关性热力图不能遗漏。
- 不要把“保存”做成含义不明的独立展示；报告不维护保存状态，模型结果只保存到模型库，报告通过浏览器打印导出 PDF。
- 不要删除用户已明确要求保留的跨数据集比较风险提示。
- 不要为了“专业”把页面设计复杂化；提示只在必要位置出现，不展示“前端接口演示，不提供真实在线服务”这类重复文案。
- 跳转不能只改可见按钮：保存结果后写入并进入模型库、模型库返回训练结果、报告返回来源页面、Hash 刷新恢复都要一起检查。
- 时序不是只能自回归；已允许多个外部特征。但用户输入数据本身不应包含未来数据，未来特征只属于 API 请求。
- 曾让分类/回归增强器误改时序结果，导致显示分类指标且操作列不固定；时序只能显示 MAE、RMSE、sMAPE、稳定性，操作列固定在表格内部右侧。
- 日历特征开关曾因样式作用域异常而显得奇怪；时序特征管理必须保留清晰开关状态和明确的“自动筛选”。

## 5. 禁止修改的部分

- 禁止修改或提交仓库中的 `ml-studio-react/`；其中存在用户自己的未提交文件。禁止把当前页面迁回 React、TypeScript、Vite 或其他构建体系。
- 禁止修改仓库根目录旧版 `v2.js`、`v3.js`–`v7.js`、对应 CSS 和旧入口；它们不是当前运行文件，仅供历史追溯。
- 禁止恢复自由画布、把目标列移到项目创建、把验证集改成测试集、加入交叉验证或按全量数据计算预处理参数。
- 禁止恢复默认勾选 Top 3、把多组参数结果当成多个实验、把报告加入主步骤、移动统一底部操作栏。
- 禁止擅自新增算法、贝叶斯调参、真实 API、登录权限、云存储、多实体时序、异常检测、时序分类或不规则事件流。
- 禁止无关重构、整体视觉重做或清空 LocalStorage。现有演示数据无需迁移；若状态结构不兼容，应提供明确重置入口。

## 6. 当前问题、限制与卡点

- 智能选型 V10.3.2 已完成时序、分类浏览器路径验证，包括热力图按钮区、「尚未应用」提示、徽章右上角定位、实验命名与旧数据迁移；旧分类、回归、时序流程回归通过。
- 宿主未安装 Node，因此未执行 `node --check app.js` 和 `node qa/smoke.test.js`；浏览器验证通过且无新增 JS 错误。
- 当前宿主的浏览器控制受 Windows 沙箱初始化故障影响，V10.2.2 尚缺一次真实浏览器点击与视觉全流程回归；隔离 DOM 测试不能替代该检查。这是当前唯一明确的验证卡点。
- 所有业务数据仍是 Mock；CSV 只持久化最多 150 行预览和字段统计，完整文件不写入 LocalStorage。
- 训练流程尚无可主动触发的失败演示；文档规定未来失败态应展示原因和“返回修改”。
- `app.js`/`app.css` 保留多代覆盖层，存在技术债。可以逐流程小步清理，但不得一次性重写，以免破坏路由、报告和模型库联动。
- 高级参数主要用于界面演示，并非每项都形成真实训练请求；接真实后端前需重新定义请求契约。

## 7. 接手后的最小操作规范

1. 只在当前交接目录内工作，先读本文件，再读详细交接文档。
2. 修改功能统一编辑 `app.js`/`app.css`，不要新增 `v11.js`、`v11.css` 式覆盖文件。
3. 每次修改都回归分类、回归、时序三条路径，尤其检查目标列、阈值、训练结果指标、报告、保存后跳转和模型库返回。
4. 执行 `node --check app.js`、`node qa/smoke.test.js` 和 `git diff --check`；浏览器能力可用时再做点击、控制台和 1024px 布局检查。
5. Git 只暂存本目录的明确文件；不得顺带提交 `ml-studio-react/` 的用户改动。
