## 0.4 覆盖层架构防踩坑

`app.js` 不是单次定义结构，而是 V3–V10.2.4 多次包装同名函数。低配 Agent 必须理解以下事实：

- 最早出现的 `modelSelectPage()` 不是唯一入口；多分类和时序都在后面覆盖它。
- 最早出现的 `experimentsPage()` 也不是最终入口；时序流程会替换页面。
- `action()` 和 `bind()` 被多次包装。只修改某个早期分支，最终页面可能完全不执行。
- `render()` 的基础页面字典仍决定页面是否可渲染；外层错误保护只负责捕获异常。
- `routeHashV910()` 与 `applyHashRouteV910()` 是当前 Hash 路由事实源；只改 `go()` 不能支持刷新恢复。
- 分类/回归结果增强器曾错误改写时序页面。智能选型必须使用自己独立的类名，不要使用可能触发旧增强器的 `result-table` 等特定类。
- v5/v6 的 DOM 注入器（`enhanceExperimentPage`、`enhanceTuningPage` 等）对**所有页面**无差别执行，不靠类名前缀隔离：只要页面出现 `.config-grid details.advanced`、`.tuning-options`、`.grid-settings`、`[data-save-result]` 等钩子，就会被注入“高级参数设置”“更多调参参数”“已保存”等旧 UI（V10.2.4 已在时序实验页实测踩坑，表现为同一页面出现两套高级参数折叠和两套网格候选值面板）。智能选型的配置页和结果页必须完全避开这些钩子类名，统一使用 `.smart-selection-v103-*` 独立类名。
- 时序任务不能直接使用 `taskKeyV9()` 判断，因为它对非回归项目可能回落到分类；必须先调用 `isForecastingV10()`。
- 新的 V10.3.0 逻辑使用统一后缀或前缀，例如函数名带 `V103`、动作名带 `smart-selection-v103`、CSS 类带 `smart-selection-v103`。
- 每个包装器只包装一次；不要在 `render()` 内反复定义包装器，否则每次渲染都会叠加事件或字符串替换。
- 新代码插入在文件末尾最终三行激活语句之前，确保首次页面渲染就能使用新逻辑。

## 0.5 推荐的内部命名约束

此处只规定命名边界，不要求照抄具体实现：

- 页面状态：使用能区分“配置页”和“结果页”的两个独立页面值。
- 选型记录集合：使用 V10.3.0 独立状态字段，不混入 `state.experiments`。

- DOM 数据属性：统一使用 `data-smart-selection-v103-*`。
- CSS：统一使用 `.smart-selection-v103-*`。
- 固定参数版本：使用单独常量，初始值明确标记为 V1；以后参数变化时递增，用于使旧记录失效。
- 模型 ID：必须继续使用现有模型目录 ID，不能只存中文名称。

## 1. 功能目标

在“模型训练”页面提供与普通模型并列的“智能选型”入口。系统先根据当前数据排除不可运行的模型、标记适合优先尝试的模型；用户自主选择多个模型组成模型池。系统以固定参数和固定预处理分别运行一次，根据任务专属指标直接推荐一个模型类型。用户可以使用推荐模型，也可以使用其他成功模型创建正式模型实验。

首版只解决“应该优先调哪个模型类型”，不替代正式实验、调参、模型报告、模型库和 API。

## 2. 不在本次范围内

- 不新增算法或模型家族。
- 不做贝叶斯调参、参数搜索或多参数方案对比。
- 不让用户编辑智能选型的参数和预处理。
- 不把智能选型结果保存到模型库。
- 不为智能选型生成模型报告或 API 配置。
- 不跨数据集共同选型，不输出跨数据集最佳模型。
- 不新增测试集、交叉验证或自由选择回测窗口策略（当前固定为扩展窗口）。
- 不展示随机种子、搜索算法、尝试次数、虚构训练耗时或冗长教学说明。
- 不使用“生成式 AI”“大模型推荐”等描述。

## 3. 页面与跳转骨架

### 3.1 完整路径

`模型训练 → 智能选型卡片 → 模型池配置 → 运行进度 → 智能选型结果 → 创建正式实验`

### 3.2 返回关系

- 模型池配置返回模型训练页面。
- 智能选型结果返回模型训练页面。
- 从选型结果创建实验后进入正式实验设置；实验页返回模型训练页面，并保留选型记录。
- 智能选型结果不能直接进入模型报告、模型库或 API。
- 浏览器刷新、前进和后退必须能通过现有 Hash 路由恢复页面。
- 所有页面切换必须先保存必要状态再更新路由，避免刷新后丢失记录。

## 4. 页面一：模型训练入口

### 页面骨架

- 在当前模型卡片列表第一位增加“智能选型”卡片，与普通模型并列。
- 卡片标签使用“推荐入口”。
- 卡片说明保持一句话：使用多个模型的固定方案快速比较并推荐后续重点模型。
- 点击普通模型仍进入原有正式实验创建流程。
- 点击智能选型进入模型池配置页。

### 启用条件

- 当前数据已经满足正式训练条件，并且已完成特征准备时可点击。
- 尚未满足条件时卡片置灰，提示“请先完成数据检查和特征准备”。
- 不在页面使用“阻断项”等术语。
- 当前任务下可运行模型少于 2 个时不能开始智能选型。
- 同一数据集正在智能选型或正式训练时，不允许再次启动训练任务。

### 验收

- 智能选型卡片不会被识别成一种算法。
- 分类、回归和时序任务均显示该入口。
- 禁用原因简短明确，不铺开数据检查说明。

## 5. 页面二：模型池配置

### 页面骨架

- 标题：`智能选型`。
- 顶部只显示当前数据集名称、任务类型和必要的选择提示。
- 主体复用模型卡片，状态仅包含：`推荐`、`可用`、`不可用`。
- 推荐模型默认选中，用户可取消。
- 可用模型允许加入。
- 不可用模型置灰、不能勾选，并显示一条具体原因。
- 底部实时显示已选择数量和“开始智能选型”按钮。
- 使用现有底部固定操作栏：左侧返回，右侧开始。

### 模型池数量

- 二分类/多分类：最少 2 个，最多 5 个，默认选中推荐度最高的 3 个。
- 回归：最少 2 个，最多 4 个，默认选中推荐度最高的 3 个。
- 时序：基线预测默认选中且不可取消；至少再选一个模型；最多 5 个；默认基线加两个推荐非基线模型。
- 少于最低数量时禁用开始按钮。
- 达到最大数量后，未选模型仍显示，但不能继续勾选，取消一个后恢复。
- 不显示预计分钟数，只显示“本次将运行 N 个固定参数方案”。

### 当前模型范围

- 二分类/多分类：逻辑回归、决策树、随机森林、KNN、LightGBM。
- 回归：线性回归、回归树、随机森林回归、LightGBM 回归。
- 时序：基线预测、指数平滑、ARIMA/ARIMAX、Prophet、LightGBM 时序。
- 多分类逻辑回归继续使用 Softmax 版本。
- ARIMA 是否显示为 ARIMAX，继续由是否纳入外部特征决定。

## 6. 模型可用性与预推荐任务

### 任务 6.1：建立独立判断层

- 将“能否运行”和“是否优先尝试”分开判断。
- 只在明确无法完成训练时标记不可用；效果可能一般只能降低推荐优先级，不能禁用。
- 判断结果必须包含状态和简短原因，页面不得自行拼接业务规则。
- 规则必须稳定、可测试，不能包含随机判断。

### 任务 6.2：硬性不可用规则

- 分类和回归没有有效训练特征：整个智能选型不可启动。
- 时序任务不要求存在外部特征；只要有效目标历史满足要求，基线、指数平滑和其他支持单变量的模型仍可运行。
- KNN：有效训练样本超过 50,000，或编码后预计特征维度超过 200 时不可用。
- 时序 LightGBM：生成固定滞后特征后，有效训练点少于 30 时不可用。
- 当前数据类型无法通过既定预处理转换为模型输入时不可用。
- 时序其他模型只要已经通过当前数据检查即可使用；季节长度不足时改用非季节配置，不禁用整个模型。
- 高缺失、类别不均衡、类别字段多、相关性弱等情况不得作为硬性禁用原因。
- 页面只显示当前任务对应的模型家族，不展示其他任务模型作为“不可用”。

### 任务 6.3：内部推荐区间

- 小数据：有效训练样本不超过 5,000。
- 大数据：有效训练样本超过 50,000。
- 少量特征：编码后不超过 20 维。
- 高维特征：编码后超过 100 维。
- 类别不均衡：最少类别占比低于 10%。
- KNN 推荐条件：不超过 5,000 行、不超过 20 维，并且以数值特征为主。
- 时序季节性明显：季节滞后相关系数绝对值不低于 0.3。
- 时序自相关明显：一阶滞后相关系数绝对值不低于 0.5。
- 时序存在已纳入外部特征时，提高 ARIMAX、Prophet 和 LightGBM 的优先级。

### 任务 6.4：推荐排序骨架

- 使用简单、确定性的规则分数，不引入不可解释的综合模型。
- 小样本、少特征、重解释场景优先线性/逻辑模型和单树。
- 大样本、类别字段多、类别不均衡时优先随机森林和 LightGBM。
- KNN 仅在满足其推荐条件时提高优先级。
- 时序季节性明显时优先指数平滑和 Prophet。
- 时序自相关明显时优先 ARIMA/ARIMAX。
- 外部特征较多或关系可能非线性时优先 LightGBM 时序。
- 所有规则分数相同时，按当前模型目录顺序保持稳定排序。
- 配置页只显示一句自然语言推荐依据；详细阈值只放在已有说明交互中，不铺满卡片。

## 7. 固定参数和预处理任务

### 共同原则

- 所有候选模型使用相同目标列、入模特征、训练/验证划分。
- 时序候选模型使用完全相同的 3 轮回测窗口（当前实现为扩展窗口，起点固定在历史最早点，只滑动验证区间；不要改成滚动窗口）。
- 预处理统计只根据训练集或每轮回测训练窗口计算。
- 使用内部固定随机状态，但页面不展示随机种子。
- 每个模型只运行一套参数，不搜索、不重试、不从多个参数结果中挑最优。
- 智能选型不读取用户其他实验中修改过的参数。
- 未在下文明确指定的字段复用该模型现有正式实验默认值。

### 固定预处理

- 逻辑回归、线性回归、KNN：数值缺失处理、类别编码、数值标准化。
- 决策树、随机森林：缺失处理和类别编码，不强制标准化。
- LightGBM：复用平台现有的缺失值和类别特征处理，不做无意义标准化。
- 时序：模型自动生成必要的滞后、趋势或季节特征；外部特征范围使用特征准备中已纳入字段；3 轮回测窗口完全复用现有时序回测函数，不重新实现。
- 页面不提供预处理控件；只允许在折叠的“平台基准配置”中查看摘要。

### 固定参数

- 逻辑回归/线性回归：复用当前平台默认正则化方案。
- 决策树/回归树：最大深度 6。
- 随机森林：200 棵树，最大深度 10。
- KNN：邻居数 5，距离加权。
- LightGBM：200 棵树、学习率 0.05、31 个叶子。
- 时序基线：有足够季节历史时使用季节朴素法，否则使用上一期值。
- 指数平滑：按已确认频率和已识别季节性选择固定趋势/季节配置；`damped` 置为 `true` 并在预设中显式带 `advanced: true`。
- ARIMA/ARIMAX：非季节主项固定为 `(1,1,1)`（均在新 schema p/q/d 范围 0–5/0–5/0–2 之内）；季节性明确且历史足够时使用平台固定季节项，并在预设中带 `seasonal: true, advanced: true`。
- Prophet：固定 `changepoint = 0.05`（趋势灵活度）、`seasonality = 10`（季节性强度）、`seasonalityMode = 'additive'` 且带 `advanced: true`。
- 时序 LightGBM：使用上述 LightGBM 参数；最大滞后按日、周、月频率使用现有平台固定值。
- “固定”表示同一次选型不搜索参数；季节周期、最大滞后等可以由频率确定。

## 9. 指标、排名与最终推荐任务

### 任务专属指标

- 二分类主指标：验证集 AUC，越高越好；辅助展示 F1、KS、训练/验证差值。
- 多分类主指标：验证集 Macro F1，越高越好；辅助展示 Accuracy、Weighted F1、Log Loss。
- 回归主指标：验证集 RMSE，越低越好；辅助展示 MAE、R²、训练/验证差值。
- 时序主指标：3 轮回测（扩展窗口）平均 MAE，越低越好；辅助展示 RMSE、sMAPE、稳定性。
- 严禁让分类/回归结果增强逻辑改写时序指标。

### 最终推荐规则

- 先按主指标排序。
- 二分类或多分类前两名主指标差值不超过 0.01 时，视为效果接近。
- 回归或时序前两名主误差差值不超过最佳值的 2% 时，视为效果接近。
- 效果接近时优先推荐更简单模型。
- 分类复杂度顺序：逻辑回归 → 决策树 → KNN → 随机森林 → LightGBM。
- 回归复杂度顺序：线性回归 → 回归树 → 随机森林回归 → LightGBM 回归。
- 时序复杂度顺序：基线预测 → 指数平滑 → ARIMA/ARIMAX → Prophet → LightGBM 时序。
- 训练/验证差距大或时序稳定性差只显示风险状态，不使用隐藏综合分改变排名。
- 至少 2 个模型成功才生成推荐。
- 只有 1 个模型成功时展示结果但不推荐，提示返回调整模型池。
- 全部失败时不保存结果，提供返回调整模型池。

### 失效规则

- 入模特征或特征版本。
- 训练/验证划分。
- 时序时间列、频率、预测期、日历特征或外部特征配置。

- 回测窗口策略（当前为扩展窗口，不是滚动窗口）。

失效记录仍可查看，但不能再据此创建实验。

- 在模型训练页面将“历史智能选型记录”与正式实验列表分开。

### 步骤 6：建立数据画像提取器

#### 做什么

只从当前数据集、字段统计和特征配置中提取推荐需要的画像，不在页面中临时计算。

画像至少包含：

- 有效训练样本数。
- 当前入模特征数。
- 预计编码后维度。
- 数值特征占比。
- 是否存在类别特征。
- 是否属于小数据、大数据、少量特征或高维特征。
- 分类任务的最少类别占比。
- 时序有效历史点数、频率、季节周期、一阶自相关、季节滞后相关。
- 时序已纳入外部特征数量。

统一计算口径：

- 有效样本数先排除无效目标，再根据当前训练集比例估算训练样本数。
- 数值和布尔特征各按 1 个维度估算。
- 类别特征按其有效唯一值数量估算编码维度；存在缺失且采用独立缺失类别时额外计 1 维。
- 只统计已纳入且可训练的字段。
- 数值特征占比以已纳入特征数量为分母；没有特征时返回 0，不返回 `NaN`。
- 分类最少类别占比只基于有效目标样本。
- 时序相关性只使用首个回测训练窗口，不能使用验证区间或未来信息。
- 无法计算相关性时返回不可用状态，不用 0 冒充真实值。

内部区间：

- 小数据：训练样本数不超过 5,000。
- 大数据：训练样本数超过 50,000。
- 少量特征：编码后维度不超过 20。
- 高维特征：编码后维度超过 100。
- 类别不均衡：最少类别占比低于 10%。
- 数值特征为主：数值与布尔特征数量占已纳入特征至少 60%。

#### 不要做什么

- 不要读取验证集结果来决定预推荐。
- 不要用页面 DOM 文本作为数据源。
- 不要返回 `NaN`、`Infinity` 或未定义的比率。
- 不要把目标列计进入模特征维度。

#### 完成检查

- [ ] 相同数据和配置重复计算得到完全相同画像。
- [ ] 类别唯一值增加时预计编码维度相应增加。
- [ ] 时序无外部特征时外部特征数为 0，但画像仍有效。
- [ ] 所有数值字段均为有限数值或明确的不可用状态。

### 步骤 9：实现预推荐评分

#### 做什么

建立确定性、可解释的内部评分。评分只决定配置页默认选择和“推荐”标签，不是最终模型结论。

建议按以下固定加分规则实现；如果现有数据无法计算某项，则该项不加分：

分类：

- 逻辑回归：小数据加 2；少量特征加 2；高维特征加 2；类别不均衡加 1。
- 决策树：小数据加 2；少量特征加 1；存在类别特征加 1。
- 随机森林：类别不均衡加 2；存在类别特征加 2；非小数据加 1。
- KNN：满足“小于等于 5,000 行、维度小于等于 20、数值特征为主”时加 4，否则不加分。
- LightGBM：大数据加 3；存在类别特征加 2；类别不均衡加 2；高维特征加 1。

回归：

- 线性回归：小数据加 2；少量特征加 2；高维特征加 2；数值特征为主加 1。
- 回归树：小数据加 2；少量特征加 1；存在类别特征加 1。
- 随机森林回归：存在类别特征加 2；非小数据加 1；特征数超过 20 加 1。
- LightGBM 回归：大数据加 3；存在类别特征加 2；高维特征加 1；特征数超过 20 加 1。

时序：

- 基线预测：固定基础分 1；历史长度接近最低要求时再加 2。
- 指数平滑：季节滞后相关绝对值不低于 0.3 时加 3；历史较短时加 1。
- ARIMA/ARIMAX：一阶自相关绝对值不低于 0.5 时加 3；存在外部特征时加 2。
- Prophet：季节滞后相关绝对值不低于 0.3 时加 3；存在外部特征时加 2；历史长度充足时加 1。
- LightGBM 时序：存在外部特征时加 3；历史长度充足时加 1；外部特征多于 2 个时再加 1。

排序规则：

- 先排除不可用模型。
- 按推荐分从高到低排序。
- 分数相同按当前模型目录顺序。
- 分类和回归取前 3 个作为默认推荐。
- 时序固定选中基线，再从其余可用模型中取前 2 个。
- 推荐理由只取该模型得分最高的一条自然语言原因；没有加分时显示“可参与固定参数对比”。

#### 不要做什么

- 不要把这个预推荐分数显示给用户。
- 不要用预推荐分数决定最终推荐。
- 不要承诺推荐模型一定最好。
- 不要让不可用模型进入前 3 个。

#### 完成检查

- [ ] 相同画像始终得到相同顺序。
- [ ] 分数相同时目录顺序稳定。
- [ ] 时序基线始终默认选中且不可取消。
- [ ] 页面没有显示内部加分数值。

- 保存生成时间、Mock 来源、固定参数摘要和预处理摘要。
- 同一配置重复生成的指标必须完全一致。
- 指标之间必须逻辑一致，不出现 MAE 大于明显不合理的 RMSE关系、概率指标越界或负误差。

分类结果：

- 二分类生成训练/验证 AUC、F1、KS 和差值。
- 多分类生成训练/验证 Macro F1、Accuracy、Weighted F1、Log Loss。
- 所有 0–1 指标限制在合法范围。
- Log Loss 为正数且越小越好。

回归结果：

- 从有效目标预览估计目标尺度；无法估计时使用稳定后备尺度。
- 生成训练/验证 RMSE、MAE、R²和差值。
- MAE 不应大于同一集合的 RMSE。
- R²保持合理范围，不生成无穷值。

时序结果：

- 复用当前三轮回测口径和现有时序数据处理规则。
- 每个模型生成三轮指标，再得到平均 MAE、RMSE、sMAPE 和稳定性。
- 智能选型记录不需要保存未来预测曲线；只保存推荐所需回测结果和快照。
- 使用外部特征的模型只能读取每轮训练窗口当时可用的信息。

失败结果：

- 只有确定性条件触发失败。
- 不要随机让示例模型失败。
- 失败对象只保存模型 ID、失败状态和一句失败原因，不参与排名。

#### 不要做什么

- 不要直接调用会依赖当前正式实验页面状态的函数而不做隔离。
- 不要用 `Math.random()` 直接生成结果。
- 不要把训练/验证差值方向写反。
- 不要让时序结果出现分类指标。

#### 完成检查

- [ ] 同一指纹运行两次结果深度一致。
- [ ] 换模型后指标不同但合法。
- [ ] 四种任务的结果字段互不串用。
- [ ] 时序有且仅有 MAE、RMSE、sMAPE、稳定性等已确认指标，且这些指标来自与正式训练同一套回测函数（`forecastBacktestWindowsV10` 等）。

### 步骤 13：实现最终推荐纯逻辑

#### 做什么

只接收成功结果数组和任务键，返回排序结果、是否能够推荐、推荐模型 ID、是否触发“效果接近优先简单”规则。

排序：

- 二分类：验证集 AUC 降序。
- 多分类：验证集 Macro F1 降序。
- 回归：验证集 RMSE 升序。
- 时序：3 轮回测（扩展窗口）平均 MAE 升序。

接近判断：

- 二分类/多分类：前两名主指标绝对差不超过 0.01。
- 回归/时序：前两名主误差差值除以最佳值不超过 2%。
- 最佳值为 0 时避免除零；此时只在两者同为 0 时视为接近。

接近时复杂度顺序：

- 分类：逻辑回归、决策树、KNN、随机森林、LightGBM。
- 回归：线性回归、回归树、随机森林回归、LightGBM 回归。
- 时序：基线预测、指数平滑、ARIMA/ARIMAX、Prophet、LightGBM 时序。

推荐最低条件：

- 成功结果至少 2 个。
- 1 个成功时显示结果但不推荐。
- 0 个成功时不保存完成记录。

#### 不要做什么

- 不要把预推荐分数加入最终排名。
- 不要构造用户看不懂的加权总分。
- 不要因为训练/验证差值警告暗中改变排名。

#### 完成检查

- [ ] 主指标差距超过阈值时推荐指标第一名。
- [ ] 差距等于阈值时按简单度推荐。
- [ ] 差距略大于阈值时仍推荐指标第一名。
- [ ] 成功数不足 2 时不返回推荐模型。

### 步骤 23：实现失效检查和级联清理

- 目标列变化。
- 二分类正类变化。
- 分类子类型变化。

- 失效记录可查看但不能创建实验。
- 数据集删除后清理其全部选型记录和当前记录 ID。
- 项目删除通过数据集级联清理选型记录。

## 20. 常见错误、原因与修复方向

### 错误 1：页面没有出现智能选型卡片

- 常见原因：只修改了最早的 `modelSelectPage()`，后续多分类或时序覆盖把改动替换掉。
- 检查方向：确认 V10.3.0 包装的是文件末尾当前生效的 `modelSelectPage`。
- 修复要求：只增加一层最终包装，不复制整页，不删除旧覆盖。

### 错误 2：点击后回到首页

- 常见原因：新页面没有加入基础 `render()` 页面字典。
- 检查方向：状态中的页面值和页面字典键是否完全一致。
- 修复要求：同步页面映射、Hash 生成和 Hash 解析。

### 错误 3：刷新结果页后记录丢失

- 常见原因：结果只放在临时变量，没有先写入 LocalStorage；或 Hash 没带记录 ID。
- 检查方向：进入结果页前是否先保存记录和当前 ID。
- 修复要求：先保存，后 `go()`。

### 错误 4：时序任务被识别成分类

- 常见原因：直接使用 `taskKeyV9()`。
- 检查方向：统一任务适配器是否先判断 `isForecastingV10()`。
- 修复要求：禁止页面各自判断任务。

### 错误 5：时序没有外部特征时智能选型被禁用

- 常见原因：把“没有入模外部特征”误当成“没有可训练输入”。
- 检查方向：时序目标历史本身就是模型输入。
- 修复要求：时序只校验目标历史、时间结构和预测期；外部特征可以为 0。

### 错误 6：相同配置生成不同结果

- 常见原因：直接调用 `Math.random()` 或指纹对象键顺序不稳定。
- 检查方向：所有随机来源是否只依赖规范化指纹和模型 ID。
- 修复要求：排序数组与对象键，使用稳定哈希或现有稳定 Mock 工具。

### 错误 7：最终推荐与主指标第一名不一致

- 常见原因：误把预推荐分数加入最终排名，或接近阈值方向错误。
- 检查方向：先按主指标排，再单独检查 0.01/2% 规则。
- 修复要求：预推荐只用于默认模型池；最终推荐不得读取它。

### 错误 8：取消后仍跳转结果页

- 常见原因：旧计时器回调没有失效。
- 检查方向：取消动作是否先递增运行令牌，所有回调是否比较令牌。
- 修复要求：清理运行态和半成品，旧回调直接返回。

### 错误 9：点击一次创建两个实验

- 常见原因：动作重复绑定，或创建前没有检查来源记录与模型映射。
- 检查方向：同一按钮是否同时有多个监听器；创建动作是否幂等。
- 修复要求：最终 `bind` 只绑定一次，先查已创建实验再新增。

### 错误 10：选型结果进入模型库

- 常见原因：复用了正式实验结果和保存结构。
- 检查方向：选型记录是否被放入 `state.experiments` 或 `state.savedResults`。
- 修复要求：选型记录保持独立，只有新建并正式训练的实验可进入模型库。

### 错误 11：配置改变后仍能创建实验

- 常见原因：只在记录创建时检查配置，没有在结果页和创建动作前复查。
- 检查方向：快照/指纹是否在关键入口重新比较。
- 修复要求：访问时检查、创建前再检查。

### 错误 12：表格让整个页面横向滚动

- 常见原因：宽表没有独立滚动容器，或固定列定位相对页面。
- 检查方向：滚动是否发生在表格卡片内部。
- 修复要求：复用现有训练结果/模型库内部滚动和右侧吸附方案。

### 错误 13：普通模型卡片或时序参数失效

- 常见原因：新 CSS/绑定器使用通用类名，覆盖旧组件。
- 检查方向：检查新增选择器是否有 V10.3.0 独立作用域。
- 修复要求：缩小选择器，只在智能选型页面执行。

### 错误 14：Git 提交包含 React 文件

- 常见原因：使用无范围的 `git add .`。
- 检查方向：提交前检查暂存文件列表。
- 修复要求：只按明确文件路径暂存当前交接目录；不得还原或提交用户 React 修改。

### 错误 15：新页面出现重复的高级参数、网格候选值或“已保存”字样

- 常见原因：v5/v6 的 DOM 注入器（`enhanceExperimentPage`、`enhanceTuningPage`）对全部页面无差别执行，识别到 `.config-grid details.advanced`、`.tuning-options`、`.grid-settings`、`[data-save-result]` 等钩子就会注入旧 UI。
- 检查方向：新页面模板是否使用了上述钩子类名；DOM 中是否出现非本功能渲染的 details、grid-settings 或 small 元素。
- 修复要求：新页面统一使用 V10.3.0 独立类名前缀，不与旧增强器钩子重叠；如确实需要复用结构，参照 V10.2.4 `bind` 末尾的时序清理模式显式移除注入物。
